# Codex Notification Bridge

入力したメッセージを、いま作業中のCodexタスクのチャットへ送るElectronアプリです。

タスク名の文字検索だけではなく、各タスクの直近の会話・作業状態・最後のやり取りの時刻をCodexに渡し、返信先として適切なセッションを判断します。

## できること

- Codex app-serverから未アーカイブの送信可能セッションを取得
- 送信先セッションを、最後のやり取りが新しい順に表示
- メッセージ入力中は文字一致で即時にフィルター
- 入力が止まるとCodexが会話の文脈込みで送信先を判定
- 選択したCodexタスクへメッセージをチャットとして挿入
- `⌘/Ctrl + Enter`、または行右端の「↵ 挿入」で送信

## 起動

```bash
npm install
npm start
```

`codex`がPATHにない場合は、実行ファイルを指定します。

```bash
CODEX_BIN=/path/to/codex npm start
```

macOSでは、左の`⌘ Command`キーだけを0.5秒長押しすると、アプリのウィンドウを前面に出してtextareaへフォーカスします。Apple標準の長押し時間に合わせた値で、別キーや右`⌘`との組み合わせはショートカットとして扱いません。この機能はmacOSのアクセシビリティ許可が必要です。ショートカットが利用できない場合も、アプリ内の入力欄と通常のクリック・キーボード操作は使えます。

## 使い方

1. 上部のメッセージ欄に、送りたい内容をそのまま入力します。
2. 入力中はローカルの文字一致で送信先セッションが絞り込まれます。
3. 入力が止まるとCodexが候補を判定し、一覧をCodexの順位に置き換えます。
4. 送信先をクリックして選択し、「↵ 挿入」または`⌘/Ctrl + Enter`で送信します。

### 表示のルール

- 入力が空のときは、全送信可能セッションを最近のやり取り順で表示します。
- 最初のCodex判定が終わった後は、文字一致候補を混ぜず、Codexが返した順位だけを表示します。
- 新しい入力を判定している間も、前回のCodex順位をそのまま表示します。
- 入力欄が一度空になると、前回の判定を破棄し、次の入力は文字一致から始めます。
- Codexの起動失敗・タイムアウト時は、文字一致の結果へフォールバックします。

## 予測の仕組み

### 1. タスク一覧を取得

`src/codex-server.js`がCodex app-serverの`thread/list`を呼び出し、未アーカイブかつ直接入力を受け付けられるタスクだけを送信先にします。

最後のやり取りの時刻には`thread/list`の`updatedAt`を使います。これは人間の送信・AIの返答のどちらも含む、スレッド上の最後の更新時刻です。

### 2. 現在地を取得

予測前に各タスクの直近4ターンを`thread/turns/list`で取得し、`src/thread-context.js`が次の情報へ圧縮します。

- 最新のユーザー依頼
- 最新のCodex応答
- 実行中または直近のコマンド
- 変更されたファイル
- ターンの状態

内部推論は取得・表示・予測プロンプトへの投入を行いません。履歴を取得できないタスクは、会話文脈が利用できないことをCodexへ明示します。

### 3. Codexで意味を判定

`src/codex-predict.js`が、読み取り専用の一時実行としてCodexを呼び出します。

- 既定モデル: `gpt-5.6-terra`
- 既定 reasoning effort: `low`
- 出力: JSON Schemaで検証した候補ID・意味スコア・確信度・理由

候補のタスク名、プレビュー、会話内容はすべて未信頼の分類対象データとして扱い、そこに書かれた指示には従いません。

### 4. オーケストレーションで最終順位を決定

Codexの意味スコアだけで決めず、`src/orchestration.js`で次の重みを合成します。

| 要素 | 重み | 内容 |
| --- | ---: | --- |
| 意味一致 | 60% | 入力とタスクの会話・作業内容の関連性 |
| 新しさ | 25% | 最後のやり取りからの経過時間 |
| 状態 | 15% | 作業中・待機中・保存済みなどの状態 |

タスク履歴は30秒キャッシュし、入力のたびに同じ履歴を取り直さないようにしています。

## 環境変数

起動時に、特定のCodexタスクを初期選択できます。

```bash
CODEX_TARGET_THREAD=<タスクUUID> \
CODEX_TARGET_NAME="<Codexに表示されている正確なタスク名>" \
npm start
```

予測モデルと reasoning effort は、必要な場合だけ上書きできます。

```bash
CODEX_PREDICT_MODEL=gpt-5.6-terra \
CODEX_PREDICT_EFFORT=low \
npm start
```

## 開発・検証

構文チェックと単体テスト:

```bash
npm run check
npm test
```

検索モデルやプロンプト、候補項目、オーケストレーションの重みを変更した場合は、固定5ケースのベンチマークも実行します。

```bash
npm run benchmark
```

ベンチマークでは、Top-1 / Top-3正解率、JSON成功率、p50レイテンシを比較します。

## 構成

```text
src/
├── main.js              Electron本体とIPCハンドラ
├── preload.js            rendererへ公開する最小IPC API
├── index.html            UIと入力・候補表示の状態管理
├── codex-server.js       Codex app-serverとのJSON-RPC通信
├── thread-list.js        タスクの正規化と送信可能判定
├── thread-context.js     直近ターンから現在地を抽出
├── codex-predict.js      Codexによる意味分類
├── ranking.js            即時文字フィルターとフォールバック
└── orchestration.js      意味・新しさ・状態の最終順位付け
```
